# C4 model

The [C4 model](https://c4model.com) describes a system at four zoom levels: context, containers, components, and code. LearnHub documents the first two; components and code are better read in the repository itself.

## Level 1: System context

Who uses LearnHub and which external systems it depends on.

```mermaid
flowchart TB
    Student(["Student"])
    Instructor(["Instructor"])

    LearnHub["LearnHub<br/>Online courses with an AI tutor"]

    Identity["Identity provider<br/>(ASP.NET Core Identity or Entra External ID)"]
    Stripe["Payment provider<br/>(Stripe or a simulated gateway)"]
    Llm["LLM provider<br/>Tutor answers"]
    YouTube["YouTube<br/>Lesson videos"]
    Email["Email provider<br/>Notifications"]

    Student -- "Browses, enrolls, studies, asks the tutor" --> LearnHub
    Instructor -- "Publishes and prices courses" --> LearnHub
    LearnHub -- "Authenticates users" --> Identity
    LearnHub -- "Charges enrollments" --> Stripe
    LearnHub -- "Generates tutor answers" --> Llm
    LearnHub -- "Embeds lesson videos" --> YouTube
    LearnHub -- "Sends emails" --> Email
```

## Level 2: Containers

The deployable units inside LearnHub and how they communicate ([ADR 0002](adr/0002-microservices-with-a-database-per-service.md), [ADR 0006](adr/0006-asynchronous-messaging-by-default.md)).

```mermaid
flowchart TB
    Browser(["Student or instructor<br/>browser"])

    subgraph System["LearnHub"]
        Web["Web frontend"]
        Catalog["Catalog API<br/>.NET"]
        Enrollment["Enrollment API<br/>.NET"]
        Progress["Progress API<br/>.NET"]
        Tutor["AI Tutor API<br/>.NET"]
        Broker[["Message broker<br/>Wolverine transport"]]

        subgraph Postgres["PostgreSQL server"]
            CatalogDb[("catalog")]
            EnrollmentDb[("enrollment")]
            ProgressDb[("progress")]
            TutorDb[("tutor")]
        end
    end

    Browser -- "HTTPS" --> Web
    Web -- "REST + JWT" --> Catalog
    Web -- "REST + JWT" --> Enrollment
    Web -- "REST + JWT" --> Progress
    Web -- "REST + JWT" --> Tutor

    Catalog --> CatalogDb
    Enrollment --> EnrollmentDb
    Progress --> ProgressDb
    Tutor --> TutorDb

    Catalog -- "CoursePublished, CoursePriceChanged" --> Broker
    Enrollment -- "StudentEnrolled" --> Broker
    Broker --> Enrollment
    Broker --> Progress
    Broker --> Tutor
```

Only the Catalog API exists today; the other containers are the target and are added module by module. The frontend technology and the message broker are not decided yet; they will get their own ADRs.
